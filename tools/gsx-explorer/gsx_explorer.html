1. Advertising, pairing and connection

The pad is a single-mode LE peripheral. Its advertising flags are 0x06 (LE General Discoverable, BR/EDR not supported), and it advertises the HID service 0x1812 with appearance 0x03C4 (Gamepad) and the name GamePad. It uses a public address, so a bond survives power cycles on both sides.

Pairing is LE Secure Connections, Just Works: no MITM protection, IO capability NoInputNoOutput, with bonding and a 16-byte key. HOGP requires an encrypted link for the reports, so a host should pair before subscribing; the ESP32 does this right after connecting. Like most HOGP devices it should reconnect to its bonded host when it wakes; that hasn't been timed yet.

Connection parameters

The Peripheral Preferred Connection Parameters characteristic (0x2A04) reads 0c 00 0c 00 63 00 90 01:

FieldRawValue
Min interval0x000C12 × 1.25 ms = 15 ms
Max interval0x000C15 ms
Slave latency0x006399 events
Supervision timeout0x0190400 × 10 ms = 4 s

Right after connecting, the pad sent an L2CAP parameter update request for 7.5–15 ms (6–12 units), latency 99 and timeout 4 s. The link settled at 15 ms. The high slave latency lets the pad sleep through up to 99 events while idle; it still sends at the next event whenever input changes, so it adds no lag. The ATT MTU negotiated to 247.

3. Report map overview

The descriptor defines three top-level collections:

IDCollectionInput payloadOutputCarries
1Generic Desktop / Game Pad12 bytes—paddle, buttons, D-pad, keypad, front buttons
2Generic Desktop / Keyboard8 bytes1 byte (LEDs)nothing in practice
3Generic Desktop / Mouse4 bytes—trackball

Report 1 is unusual: a Game Pad collection that also contains Keyboard-page (0x07) usages as 1-bit variable fields. That is how the D-pad, keypad and two front buttons are delivered. Linux splits it into a joystick device plus keyboard keys, which is why generic hosts map the pad strangely.

5. Report 2 — keyboard

A standard 8-byte boot-style keyboard report: byte 0 holds the modifier bits (usages 0xE0–0xE7), byte 1 is reserved, and bytes 2–7 are a 6-key array (usages 0x00–0xFE). The output report is 5 LED bits (Num, Caps, Scroll, Compose, Kana) plus 3 bits of padding. No captured input ever used this report; all keyboard-page controls arrive in report 1 instead.

6. Report 3 — mouse / trackball (4-byte payload)

ByteUsageTypeNotes
0Button 1–88 × 1 bitalways 0 (the trackball has no buttons)

Each report carries the motion since the previous one, saturated to ±127. On fast rolls the pad hits that limit and the excess is lost: 4.8% of trackball reports in the ESP32 log were clipped. Shorter connection intervals reduce clipping only if the pad actually sends more often; this hasn't been tested yet.

8. Vendor services

FF12 is the firmware update (OTA) service. Characteristic FF15 reads back FOTA. Writing to it can put the pad into update mode or brick it, so leave it alone. The explorer asks for confirmation before any write to this service.

FFF0 holds a write characteristic (FFF1), a notify characteristic (FFF2) and a 128-bit custom characteristic with read, write and notify. None of them sent anything during the captures. This is the most likely channel for SmartGlow (lighting the controls a game uses) and the centre screen, which the Gamestation console drives. The command format is unknown; it would need a capture of what a Gamestation Go writes here, for example by sniffing the link.

SmartGlow light numbering

The Go's own gsgparm tool (in /sdcard/bin) switches the console's lights through Linux LEDs /sys/class/leds/key_led1…key_led23 (brightness 255 = on, 0 = off). It doesn't talk to the pad itself, but the pad has the same set of lights, so this is the likely order on the wire too:

9. Quirks and host notes

Paddle decoding

Byte 2 of report 1 is the paddle's position, not its motion. It counts 0–80 (81 steps per revolution) and wraps both ways (observed 0→78 and 80→1). A host that treats it as an ordinary axis sees a full-scale jump at every wrap. To get spinner motion, take the shortest-path difference:

d = new - old
if d >  40: d -= 81
if d < -40: d += 81
spinner += d

Several steps can pass between reports, so always apply the wrap correction.

Descriptor bugs

  • The mouse X/Y Logical Minimum is encoded 16 08 ff, which decodes to −248. The real range is −127…127; strict parsers may reject or misscale it.
  • Report 1 declares Button usage maximum 15 but 16 bits; the 16th bit has no defined usage.
  • A fourth Report characteristic (ID 4) exists in GATT with no matching collection in the map.

Timing

Reports are sent only when something changes. On the ESP32 link most consecutive reports were 15 ms apart, matching the connection interval. Gaps of 0–2 ms also showed up, meaning the pad sends more than one notification per connection event while the trackball and paddle move together.

Linux

hid-generic exposes the paddle as ABS_Z, the trackball as a mouse, and the D-pad, keypad, Settings and Home as keyboard keys. That's why games and emulators see an odd mix of devices, and it's the main reason a remapping dongle helps.

Lights probe. Writes test patterns to the pad's vendor service FFF0 (most likely where SmartGlow lives) while you watch the orange lights. It never offers the firmware-update service FF12. The likely worst case is the pad disconnecting or restarting; if that happens the sweep pauses and the log shows the last payload sent. Needs GSX Explorer firmware gsx-0.2 or later for the error codes.
